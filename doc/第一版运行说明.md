# WorkLink 第一版运行说明

版本：0.1.0；日期：2026-10-02。本文记录实际实现及验证边界，原始讨论约束保留在需求文档。

## 1. 组件与目录

| 组件 | 位置 | 职责 |
|---|---|---|
| 本地服务 | `src/worklink` | Telegram 风格接口、持久化输入、菜单/消息映射、操作租约 |
| Edge 扩展 | `src/edge-extension` | 自聊身份校验、读取可见 DOM、草稿保护、执行及确认操作 |
| 插件补丁 | `scripts/patch-omp-plugin.py` | 本机接口、HTTP 传输、未开放指令明确拒绝 |
| 私有配置与状态 | 仓库外 `WorkLink-private` | 配置、密钥、SQLite、OMP 会话及本地证据 |

Python 服务不依赖第三方包。浏览器适配密钥与 OMP Bot 密钥不能混用。

## 2. 初始化与服务启动

```powershell
python -X utf8 scripts/setup-local.py
```

默认私有目录为仓库同级 `WorkLink-private`，也可用 `--private-dir <EXTERNAL_PRIVATE_DIR>`。真实自聊标题只写入该目录 `config.json` 的 `teams.selfChatDisplayName`，不能写到源码或公开示例中。

```powershell
.\scripts\start.ps1
# 自定义外部配置：
.\scripts\start.ps1 -Config <EXTERNAL_CONFIG_FILE>
```

默认监听 `127.0.0.1:8765`。HTTP 接口校验 Host，拒绝普通网页 Origin。适配接口使用 Bearer 适配密钥；Telegram 接口使用独立 Bot 密钥。`GET /health` 仅用于本机状态检查，不返回账号和密钥。

## 3. 加载 Edge 扩展

1. 在 Edge 扩展管理中开启开发人员模式，选择“加载解压缩的扩展”。
2. 选择项目中的 `src/edge-extension`。
3. 打开 WorkLink 设置，填写本机地址和私有目录 `secrets/adapter-token.txt` 的内容。
4. 刷新 Teams 自聊页，保持可见并滚动至最新消息；用“检查连接”查看状态。

扩展只匹配 `https://teams.cloud.microsoft/*` 并访问本机，不读取 cookie、密码或其他站点。密钥保存在扩展自己的受信任存储，Teams 内容脚本不直接取得密钥。标题必须完全匹配，标题 DOM 必须只有一个参与者。已有草稿和正在编辑的消息不会被覆盖。

第一版每秒检查可见页面。Teams 使用虚拟列表，隐藏标签页、关闭页面、页面冻结、滚动至历史或消息尚未渲染都可能影响采集；本版不是 Microsoft Graph 的后台订阅。只允许一个活动适配实例和一个 getUpdates 消费者。

## 4. OMP 插件接入

采用 [evandrodevbr/oh-my-pi-telegram](https://github.com/evandrodevbr/oh-my-pi-telegram)，固定提交 `033a92f3bb56cef5e71a6389b99ca72e2132a77a`，包版本 `0.22.0-evandro.1`。这是本版参考实现，并不代表已确认其使用量最多。上游要求 Node.js 22.19+、OMP 16.5.2+。上游源码及许可证留在外部克隆中，不随 WorkLink 重新打包。

```powershell
git clone https://github.com/evandrodevbr/oh-my-pi-telegram <EXTERNAL_PLUGIN_DIR>
git -C <EXTERNAL_PLUGIN_DIR> checkout 033a92f3bb56cef5e71a6389b99ca72e2132a77a
python scripts/patch-omp-plugin.py <EXTERNAL_PLUGIN_DIR>
python -X utf8 scripts/prepare-omp.py
```

补丁核验提交和三个源文件哈希。重复执行匹配的补丁不会改变文件；其他版本或已有冲突修改会拒绝。专用配置脚本创建外部 `omp-agent/telegram.json`，设置虚拟 Bot、owner `1001`、HTML 文字输出，关闭草稿预览；已有配置不覆盖。

链接已修补的本地插件目录，避免 npm 安装时换成未修补版本：

```powershell
$env:PI_CODING_AGENT_DIR = '<EXTERNAL_PRIVATE_DIR>/omp-agent'
omp plugin link <EXTERNAL_PLUGIN_DIR>
omp plugin list --json
omp plugin doctor
```

```powershell
.\scripts\start-omp.ps1 -PluginPath <EXTERNAL_PLUGIN_DIR>
```

启动入口设置本机 `WORKLINK_TELEGRAM_API_BASE`、专用 agent 目录及 IPv4 传输，退出后恢复环境。它不会安装 OMP或自动复制模型凭据。先在专用配置中准备有效模型授权与默认模型；交互启动时在 OMP 执行 `/telegram-connect`，再在 Teams 新发 `/chat /start`。默认工作目录为仓库外 `omp-workspace`，可用 `-Workspace <EXTERNAL_WORKSPACE>` 指定。

已确认 OMP 18.4.8，插件已链接、启用并在真实 OMP 中运行。OMP 的插件包目录共享，`PI_CODING_AGENT_DIR` 隔离的是会话、模型配置和 Telegram 状态，不能据此假定包安装目录也隔离。健康检查无错误；链接安装可能提示缺少包目录清单。跨 Windows/Ubuntu 部署需要另行设计安全接入；本版不打开局域网监听。

无界面常驻运行并自动连接：

```powershell
.\scripts\start-omp.ps1 -Headless
```

本地服务及已配置的 Teams 页需同时运行。入口启动真实 OMP RPC 会话，自动执行 `/telegram-connect`，确认轮询已激活后显示就绪提示；Ctrl+C 断开并停止该会话。输出与错误只写入外部 `omp-agent/logs`，不回显真实消息或凭据。工作区仍可使用 OMP 正常工具，未启用自动批准。只运行一个 WorkLink OMP 会话，避免轮询消费与锁冲突。

本次联调使用已有本机授权的外部副本与专用模型配置；原有 OMP 配置未改动。原默认模型请求曾鉴权失败，专用配置切换到已有授权的模型后验证成功。启动脚本不会自动复制授权，其他机器需要在专用配置中自行登录；OAuth 副本刷新可能影响同一账号的其他会话，需要独立运行时优先单独登录。


## 5. 输入与按钮语义

- `/chat` 区分大小写，必须紧接至少一个空白和非空正文。`/chatting`、仅 `/chat`、普通消息均忽略。
- 只移除外层前缀与分隔空白，保留内部指令、参数和后续换行；重新生成 UTF-16 `bot_command` 实体。
- 插件控制命令、注册的 Telegram 扩展命令和提示模板经过原有分发。未开放的指令明确回复不支持，不进入普通模型提示；并非所有 OMP TUI 专属命令都能远程使用。
- 菜单编号为 `k` 加 12 位随机十六进制字符串。有效 `/choose <编号> <正整数>` 转成保留原始 `callback_data` 的 `callback_query`。
- URL 按钮显示 URL；其他按钮类型明确拒绝。菜单在回复确认成功后生效，替换或删除回复使旧菜单失效。
- 同一 Teams 消息 ID 只消费一次。不同新消息重复选择是否有效仍由插件菜单处理，不统一限制所有设置菜单只能选择一次。
- 无效或过期选择忽略，不执行其他菜单。输入修改不重提；输入删除不代表取消。取消需使用 `/chat /abort` 或 `/chat /stop`。

## 6. Telegram 接口范围

路径为 `/bot<BOT_TOKEN>/<method>`，返回 `ok/result` 或 `ok=false/error_code/description`；接受 GET 参数、JSON POST 或表单编码 POST。

| 方法 | 实际行为 |
|---|---|
| `getMe`、`getChat` | 中性虚拟身份、单个 private chat，无 topics |
| `getUpdates` | 长轮询、offset 确认、负 offset、limit、allowed_updates、单消费者 |
| `sendMessage`、`sendRichMessage` | 带 `omp：` 的纯文本，确认已发送后返回消息身份 |
| `editMessageText`、`editMessageReplyMarkup` | 只修改服务回复，校验原文和身份 |
| `deleteMessage` | 只删除服务回复，要求原 ID 的已删除标记 |
| `answerCallbackQuery` | 确认已知回调，不模拟 Teams 弹窗 |
| `setMyCommands`、`getMyCommands`、`deleteMyCommands` | 本地保存，不创建 Teams 原生菜单 |
| `deleteWebhook`、`getWebhookInfo` | 单轮询兼容，不注册 webhook |
| `sendChatAction` | 兼容空操作，不显示 Teams 打字提示 |
| 其他方法 | 501；草稿、附件、语音和文件 API 均未实现 |

HTML 转为纯文本，样式与链接标签不等同 Telegram 富文本；正文中请显式包含需要保留的 URL。回复参数不显示为 Teams 原生引用。超出正文长度/批次限制会拒绝。

## 7. 恢复与未知结果

首次连接用当前时刻和可见消息 ID 建立基线，忽略之前的历史指令。之后读取稳定 `data-mid`，持久化去重、输入更新、菜单及服务回复映射。重启不清空这些状态。

固定插件自身启动同步使用 `getUpdates(offset=-1)`，可能舍弃此前未消费积压。重要任务在双方连接后发送，不把本版当作无限离线收件箱。

执行前浏览器保存操作租约和可见消息基线。未知结果不重发，重启不重放已租出的操作。重新看到唯一匹配结果时可补确认，否则必须人工核对。

确认操作确实没有发送/保存时，停止服务后执行：

```powershell
python -X utf8 scripts/reconcile.py
python -X utf8 scripts/reconcile.py --job <JOB_ID> --confirm-not-applied
```

再从扩展设置清除未确认记录、重启服务并刷新自聊。回复已存在时保留记录，让扩展补确认，不使用“未执行”方式清理或手动重发。菜单/消息已被人工改变而无法唯一确认时，保留数据库和本地证据诊断。若原插件调用已经因未知结果返回错误，后续补确认不保证插件恢复旧菜单登记；恢复连接后重新发送 `/chat /help` 或 `/chat /start` 生成新菜单。

## 8. 验证记录与限制

- WorkLink：19 项 Python 测试、13 项扩展模拟测试通过，覆盖指令、回调、编辑删除、去重、历史基线、长轮询、重启不重放、草稿、鉴权隔离、诊断脱敏、延迟输入、粘贴通道及发布包白名单。
- 固定插件：实际 HTTP 对接本地 `getMe/getChat`，默认传输和强制 IPv4 均通过；独立指令分发探针通过，34 项上游命令测试通过。
- 真实 Teams：读取新 `/chat /model` 并生成指令事件；通过浏览器操作和服务租约确认测试回复的发送、编辑、删除。证据仅保存在外部私有目录。
- 已安装扩展：自聊身份匹配、持续连接及新 `/chat /status` 指令自动采集已经实测，输入可被参考插件读取。
- 自动发送：参考插件调用本地服务，已安装扩展自动粘贴、点击当前发送按钮，并以真实已发送消息 ID 确认成功，无浏览器工具代发。
- 选项回调：`/choose` 自动采集并转换为原始回调数据，参考插件确认成功。
- 自动编辑与删除：参考插件调用服务后，扩展自动替换正文、保存，保持原消息 ID，正文和已编辑标记实测匹配；随后自动删除，确认原消息 ID 的删除标记。最终验证未使用浏览器工具代为编辑或删除。
- 页面适配：输入完成后重新查找当前发送按钮；按目标消息 ID 定位消息工具栏，编辑使用直接按钮、删除打开更多选项；菜单使用可访问标签；发送与编辑统一通过粘贴通道并等待选区同步。已有草稿和并发输入仍受保护，结果未知时仍停止重试。
- 真实 OMP 会话：已安装并启用固定插件，真实 OMP 接收 Teams `/chat`，调用已有授权的模型，回复经扩展自动返回 Teams。无界面自动连接入口已运行并确认轮询激活。
- 帮助菜单与真实选项：多段帮助菜单自动发送并确认；此前未确认回复在重新加载后成功补确认，没有重发。重新生成菜单后，`/choose` 调用真实 OMP 回调，把原消息自动编辑为思考级别菜单；返回主菜单也以相同消息 ID 自动编辑并确认。回复比较兼容 Teams 扩展的空白段落及不换行空格，用户输入原文仍保持。

编辑器输入方式参考 [CKEditor 官方粘贴处理说明](https://ckeditor.com/docs/ckeditor5/latest/framework/deep-dive/clipboard.html)。模拟测试验证策略和保护逻辑，不代替 Teams 实际行为测试；发送及编辑均通过编辑器粘贴通道，构造的粘贴数据仅包含本次回复，不读取系统剪贴板。
- 上游完整测试未全通过：传输测试 32/34，另外两项依赖 Unix 权限；模板/路径测试也含 Windows 路径和 `/tmp` 假设。没有修改上游测试绕过失败；本版不集成这些文件传输能力。

浏览器工具禁止访问 `edge://extensions/`，因此扩展加载和设置由用户手动完成，不通过绕过策略的方式安装。
