# 隐私隔离与发布

公开仓库只保存通用代码、虚构测试数据、脱敏文档、配置模板和参数化技能。真实账号、企业资源地址、密钥、浏览器会话、消息正文、附件、数据库、日志和截图保存到仓库外私有目录。

首次公开前先保留原始资料并比对文件哈希，再整理公开副本。以后也不要将本地现场直接附加到公开 Issue、PR、提交说明、构建日志或 Release。

## 上传入口

仓库本地 Git hooks 在提交前检查暂存内容、推送前检查可达历史。检查使用文件允许清单、私有类型限制、通用敏感模式和可选的仓库外禁传词。hooks 可被 Git 的跳过选项绕过，因此不能代替人工审阅；CI 在上传后复查，不能撤回已经公开的数据。

GitHub 的 secret scanning 和 push protection 用于补充支持的密钥类型。项目自定义规则不声称能够自动识别所有隐私内容。

## 配置和数据

- 配置模板仅使用虚构值；真实配置不进入 Git。
- 本地 Git 作者邮箱使用 GitHub noreply 地址。
- CI 不需要企业账号、Teams token、登录会话或真实业务数据。
- 真实账号联调在本地完成，公开测试使用虚构消息与站点。
- 日志的真实内容只留本地。服务实现时还需默认脱敏日志、认证请求和限制数据访问。

## 发布入口

运行 `scripts/release.ps1 <版本号>`，检查工作区、上传内容及测试，更新 `VERSION`，创建标签并原子推送。Actions 再检查，并从指定标签的已跟踪文件按允许清单生成 ZIP 和校验值，然后创建 GitHub Release。

首次建仓库不自动发布版本包。当前代码尚未实现桥接服务，现阶段版本包只是文档、技能及维护脚本。许可证尚未选定，不能把公开可见当作 MIT 或其他许可证授权。

程序更新不覆盖仓库外配置和数据。未来数据库升级须另外定义备份、迁移及回退策略。
